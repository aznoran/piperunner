Pipe Runner

Мобильная аркада: вагонетка едет по трубам, которые игрок выкладывает на ходу. Механика построения пути из Pipe Dream, скрещённая с бесконечным раннером.

ДВИЖОК: GODOT 4.x ЯЗЫК: GDSCRIPT ПЛАТФОРМА: ANDROID + IOS ОРИЕНТАЦИЯ: PORTRAIT РЕФЕРЕНС: pipe-runner-v6.html

01Что нужно сделать

Портировать рабочий HTML5-прототип (pipe-runner-v6.html) на Godot 4 с сохранением всей игровой логики и добавлением функционала из раздела 10. Прототип приложен и является источником истины по механике — при расхождении текста и кода прототипа побеждает прототип.

Почему Godot и GDScript. Нет обязательной заставки движка при запуске: лицензия MIT, boot splash отключается или заменяется на свой в Project Settings → Application → Boot Splash. Лёгкий билд для 2D, нет Runtime Fee.

Почему не C#. В Godot 4 поддержка C# на мобильных платформах до сих пор помечена как экспериментальная: на Android только архитектуры arm64 и x64, требуется .NET 9+, во вкладке экспорта висит предупреждение. GDScript такого ограничения не имеет и экспортируется на iOS и Android без оговорок. Для этой игры язык не является узким местом — вся логика простая и не упирается в производительность скриптов.

Если проект всё же переедет на Unity — только версия Unity 6 LTS или новее, там «Made with Unity» отключается на бесплатной Personal-лицензии. На более старых версиях с Personal сплэш убрать нельзя.

02Игровой цикл

  1. Вагонетка стоит на стартовом отрезке труб и не двигается, пока игрок не поставит первую трубу.
  2. Игрок получает трубу из очереди и ставит её в любую свободную клетку поля.
  3. Вагонетка едет по построенным трубам, поворачивая по коленам.
  4. Топливо тратится за каждую пройденную клетку. Кристаллы на поле пополняют его.
  5. Забег заканчивается, когда вагонетка приезжает в клетку без подходящей трубы либо кончается топливо.

Ключевой конфликт: какая труба выпадет — не твой выбор, куда её положить — полностью твой.

03Поле и координаты

  • Сетка 7 колонок (COLS = 7), бесконечная вверх.
  • col растёт вправо (0…6), row растёт вверх.
  • Размер клетки CELL = ширина_экрана / 7. Клетки квадратные.
  • Хранить занятые клетки в словаре по ключу Vector2i(col, row) — плотный массив не подойдёт, поле бесконечное.
Если игрок жалуется на промахи — предусмотреть переключение на 6 колонок константой. Клетки станут крупнее на 17%.

04Типы труб

Труба описывается набором сторон, на которые она открыта. Направления: U вверх, D вниз, L влево, R вправо.

Правило проезда

public enum Side { U, D, L, R }

static readonly Dictionary<PipeType, Side[]> Pipe = new() {
    { PipeType.V,  new[]{ Side.U, Side.D } },
    { PipeType.H,  new[]{ Side.L, Side.R } },
    { PipeType.UR, new[]{ Side.U, Side.R } },
    { PipeType.UL, new[]{ Side.U, Side.L } },
    { PipeType.DR, new[]{ Side.D, Side.R } },
    { PipeType.DL, new[]{ Side.D, Side.L } },
    { PipeType.X,  new[]{ Side.U, Side.D, Side.L, Side.R } },
};

// null означает, что труба не принимает вагонетку с этой стороны
public static Side? ExitSide(PipeType type, Side entry)
{
    var sides = Pipe[type];
    if (Array.IndexOf(sides, entry) < 0) return null;
    if (type == PipeType.X) return Opposite(entry);   // перекрёсток — насквозь
    return sides[0] == entry ? sides[1] : sides[0];
}

entry — сторона клетки, через которую вагонетка въехала. Если вагонетка едет вверх, она въезжает в следующую клетку через её нижнюю сторону, то есть entry = "D".

05Движение вагонетки

Состояние: col, row, entry, t (прогресс 0…1 до следующей клетки).

t += speed * delta
while t >= 1.0:
    t -= 1.0
    step_cart()

Шаг вагонетки — step_cart()

  1. Взять трубу в текущей клетке. Нет трубы → смерть «Derailed».
  2. Вычислить exit_side. Null → смерть «Derailed».
  3. Посчитать следующую клетку. Вышли за края поля по колонке → смерть «Off the edge».
  4. В следующей клетке нет трубы или она не открыта нужной стороной → смерть «Derailed».
  5. Иначе: перейти в клетку, пометить трубу как flooded (пройденная), начислить очки, проверить кристалл, списать топливо.
Критично для ощущения игры. Позиция вагонетки на экране должна считаться как дробная интерполяция между текущей и следующей клеткой по t. В ранней версии прототипа она хранилась целыми клетками — вагонетка телепортировалась, камера дёргалась рывками, и игрок систематически промахивался мимо клеток. Замер разницы: рывки камеры упали с 6.5 px за кадр до 0.63 px, разброс — в 34 раза.

06Камера

  • Следит за дробной позицией вагонетки, держит её на 72% высоты экрана.
  • Сглаживание: cam_y += (target - cam_y) * min(delta * 9, 1).
  • Мёртвой зоны быть не должно. Она копит расхождение и сбрасывает его рывком — проверено, стало хуже.
  • Заморозка при касании: пока палец на экране, камера стоит. Вагонетка при этом продолжает ехать.
  • Страховка: разморозить принудительно через 1.6 секунды, чтобы вагонетка не ушла за кадр.

07Управление

Схема «нажал — потянул — отпустил». Мгновенная установка по тапу не подходит: между «увидел клетку» и «коснулся» проходит около 200 мс, за которые поле уезжает.

СобытиеПоведение
нажатие на слот HOLDобмен трубы, палец дальше не обрабатывается
нажатие на нижнюю полосу очередиигнорируется (не поле)
нажатие на полезаморозить камеру, запомнить клетку под пальцем, показать призрак трубы
движение пальцапересчитать клетку, обновить призрак
отпусканиепоставить трубу, если можно; разморозить камеру
отмена жестасбросить призрак, разморозить камеру

Призрак трубы: зелёная подсветка клетки плюс силуэт трубы, если поставить можно; красная подсветка, если нельзя.

08Установка труб

Куда ставить нельзя

  • За пределы колонок 0…6.
  • В камень.
  • В трубу с флагом flooded — вагонетка по ней уже проехала.
  • В клетку, где сейчас вагонетка.
  • Выше max_row + 22 и ниже max_row - 6, где max_row — максимальный достигнутый ряд.

Перезапись

Поставить трубу поверх непройденной трубы можно, но это стоит 7 топлива. Показать всплывающий текст -7 над клеткой.

Это ядро скилла, не мелочь. Примерно 45% труб не подходят к текущему стыку. Их нельзя пропустить — надо куда-то положить, чтобы добраться до следующей. Кто сбрасывает мусор позади вагонетки, живёт вдвое дольше того, кто кидает вперёд и врезается в собственный хлам. В симуляции: 13 клеток против 27. Ограничение «не ниже max_row - 6» задаёт размер этой мусорной зоны — не убирать.

09Слот HOLD

  • Пустой слот: тап кладёт туда текущую трубу и подаёт следующую из очереди.
  • Занятый слот: тап меняет местами трубу в руке и трубу в кармане.
  • Обмен не прокручивает очередь — иначе игрок бесконечно перебирал бы трубы. Бесплатный пропуск ровно один, самый первый.

Генерация мира

  • Ряды создаются лениво, на 18–20 рядов вперёд от вагонетки.
  • Камни: не появляются до ряда 16. Дальше плотность min(0.05 + (row-16)*0.0012, 0.14).
  • Кристаллы: по одному через каждые 2–4 ряда, в свободной клетке ряда.
  • Комбо: растёт за каждый подряд собранный кристалл, даёт 10 * min(combo, 5) очков. Обнуляется при промахе.
Баланс не финальный. Цифры выше проверены только ботами, а боты умеют лишь продлевать путь и не умеют строить маршрут заранее. Реальный потолок игры не измерен. Все константы вынести в один ресурс GameBalance.tres, чтобы правились без пересборки.

Технические требования

  • Рендер трубы — Line2D или спрайт-атлас; для поля подойдёт TileMapLayer с 7 тайлами труб.
  • Сохранение через ConfigFile или FileAccess в user://: рекорд, валюта, купленные апгрейды.
  • Целевая частота — 60 FPS на бюджетном Android. Не создавать узлы в цикле кадра; частицы через пул.
  • Тактильный отклик на постановку трубы и на сбор кристалла (Input.vibrate_handheld(20)).
  • Boot splash отключить или заменить на свой: Project Settings → Application → Boot Splash → Image.
  • Поддержка вырезов и «чёлки»: HUD в SafeArea, нижняя полоса очереди выше системного жеста «домой».

13Сборка под iOS и Android

Общее

  • Godot стандартной сборки (не .NET) — экспорт на обе платформы без оговорок.
  • Ориентация: portrait, поворот экрана запрещён.
  • Рендер: Mobile. Forward+ для 2D-игры избыточен и жрёт батарею.
  • Разрешение: Stretch Mode = canvas_items, Aspect = expand — поле по ширине, длина экрана добирается по высоте.
  • Boot splash заменить на свой или отключить целиком.

Android

  • JDK 17, Android SDK, включить Use Gradle Build для подключения рекламы и сервисов.
  • Архитектуры: arm64-v8a обязательно, armeabi-v7a опционально. x86_64 — только для эмулятора.
  • Формат публикации — .aab, подписанный релизным keystore. Keystore не хранить в репозитории.
  • Минимальная версия API — 24 и выше.
  • Нижняя полоса очереди должна быть выше зоны системного жеста «домой».

iOS

  • Требуется macOS с Xcode; Godot экспортирует Xcode-проект, финальная сборка идёт в нём.
  • Apple Developer Program обязателен для публикации и для теста на устройстве через TestFlight.
  • Bundle ID, иконки всех размеров, launch screen.
  • Минимальная версия iOS — 13.
  • HUD размещать внутри безопасной зоны — учесть «чёлку» и Dynamic Island.
  • Если будет реклама или аналитика — заполнить App Tracking Transparency и Privacy Manifest, иначе ревью завернёт.

Тактильный отклик

Input.vibrate_handheld(20) на постановку трубы и (40) на сбор кристалла. На Android работает из коробки; на iOS короткая вибрация поддерживается начиная с Godot 4.2. Вынести в один метод, чтобы легко отключить в настройках.

14Приёмка

  • Вагонетка стоит на месте до первой поставленной трубы, топливо не тратится.
  • Прокрутка поля равномерная, без рывков при переходе между клетками.
  • Пока палец на экране, поле не двигается; через 1.6 с камера освобождается сама.
  • Призрак трубы следует за пальцем и корректно краснеет над недоступной клеткой.
  • Труба ставится в ту клетку, где палец был в момент отпускания.
  • HOLD меняет трубы местами и не позволяет прокручивать очередь бесконечно.
  • Перезапись непройденной трубы снимает 7 топлива и показывает это на экране.
  • Проезд по кристаллу пополняет бак и наращивает комбо; промах комбо обнуляет.
  • Три причины смерти отрабатывают раздельно: Derailed, Off the edge, Out of fuel.
  • Рекорд переживает перезапуск приложения.
  • При запуске нет заставки движка (проверено на релизной сборке, не в редакторе).
  • Сборка ставится и запускается на реальном Android-устройстве и на iPhone.
  • HUD не залезает под «чёлку» и Dynamic Island; очередь не конфликтует с системным жестом.
  • 60 FPS удерживаются на 300+ труб на поле.
Прототип-референс: pipe-runner-v6.html — открывается в любом браузере, вся логика в одном файле, константы в блоке tuning сверху.
